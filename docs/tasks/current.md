## 当前版本：v0.5 前端接入真实接口（进行中，2026-10-31）

- 背景：后端 v0.3/v0.4 已交付完整业务接口与治理能力，`web/` 仍是 UI 骨架（除登录与工作台）。本轮把管理端与考生端全部接到真实 `/api/v1`。
- 目标：跑通「建题 → 组卷 → 审核 → 建考试 → 编排 → 发布 → 考生作答 → 交卷 → 阅卷（双评/仲裁）→ 成绩发布 → 分析」的端到端可用界面，监考中心接 WebSocket 实时流。

### 做什么

1. 数据地基：`apiRequest` 暴露 `pagination`；`queryKeys` 工厂；按模块封装 API 与 TypeScript 类型；路由与侧栏按角色可见（未登录跳转已有）。
2. 系统管理：账号与角色（筛选/新建/编辑/停用/重置密码）、组织架构（校区+班级）、审计日志检索、通知中心与顶栏真实未读。
3. 题库：题库列表/创建、题目多条件筛选与分页、按题型的创建/编辑抽屉（content/answer/score_rule 表单）、发布与版本提示。
4. 试卷与考试：试卷列表、组卷编辑器（固定/AB 选题 + 随机规则）、提交审核与审核通过；考试列表、创建表单（选卷/时间窗/规则/考生与班级编排）、发布、考生名单、监考与阅卷名单配置。
5. 阅卷、成绩与分析：任务池（我的/待认领）、评分抽屉（轮次、双评、仲裁标记、匿名）、成绩列表与逐题明细、按考试发布、成绩分析（统计卡 + 分数段自绘条形）。
6. 监考中心：考试选择、概览卡、事件流与筛选、处置弹窗、WebSocket 实时推送（断线重连 + 轮询兜底）。
7. 考生端：我的考试、作答页（题目导航、答案自动保存与乐观锁冲突处理、倒计时、交卷确认）、我的成绩。

### 不做什么（v0.5 明确排除）

- 不改后端接口、迁移与数据库；确实缺接口时先记录，不自行发明后端行为。
- 不引入图表库和第二套组件库；分数段分布用轻量自绘 + antd 原生组件。
- 不做 Excel 导入导出、文件/媒体上传、富文本与公式、人脸核验与 AI 检测、编程题沙箱（后端未实现，界面不做假按钮）。
- 不实现题序/选项乱序等"稳定随机"（后端未提供，不用前端伪实现）。
- 不做深色模式；不改登录页与工作台的既有视觉。

## v0.4 监考实时化与考试治理（2026-10-31 完成）

- 目标：补齐 v0.3 遗留的后端协同与治理能力，让监考、阅卷与考试生命周期真正可运营。
- 前端本轮不接业务接口；仅把侧栏版本标签同步为 v0.4，工作区已有的未提交登录页改动保持不动。

### 做什么

1. 监考 WebSocket：JWT 鉴权、按考试房间订阅、事件/开考/交卷实时推送、心跳与断线清理。
2. 考试生命周期：到期自动结束考试，未入场考生自动标记缺考；与自动收卷协同。
3. 阅卷协同：考试级阅卷教师配置、任务自动分配、双评（分差阈值）与三评仲裁、最终成绩合成。
4. 访问范围：监考员仅访问被分配场次；阅卷教师仅见自己的任务；超管/考务不受限。
5. 站内通知：考试发布、成绩发布自动生成通知并去重；通知列表与已读继续可用。
6. 验收：扩展 E2E 覆盖 WebSocket、双评/仲裁、通知、缺考/结束；更新文档。

### 不做什么（v0.4 明确排除）

- Excel 导入导出、文件上传与媒体存储（下一轮）。
- 短信/邮件真实发送、编程题沙箱、人脸核验与 AI 检测（需要外部服务/基础设施）。
- 校区/班级级数据范围强制（本轮只做监考/阅卷的资源级范围）。
- 前端接真实接口（下一阶段）。

### 实现要点

- 迁移 `0004_exam_staff_review_rounds_notifications.sql`：新增 `exam_proctors`、`exam_reviewers`；`review_tasks.round`（1-3）+ `(attempt_id, question_id, round)` 唯一索引；`notifications.source_type/source_id` + 去重部分唯一索引。
- 事件通道：`store.RealtimeEvent` + `RealtimePublisher` 接口，`main` 里 `st.UseRealtime(api)` 注入 httpapi 的房间广播，store 不依赖 HTTP 包。
- 广播事件：`exam_published`、`exam_closed`、`attempt_started`、`attempt_submitted`、`proctor_event`、`proctor_event_handled`。
- WebSocket：`GET /api/v1/proctor/exams/{examId}/ws?token=`（浏览器无法给 WS 带 Authorization 头，故该路由自带鉴权且不在 authenticate 组内）；Origin 白名单校验、60s ping / 75s pong 超时、房间上限 64、慢消费者断开；`statusRecorder` 增加 `Hijack` 以兼容日志中间件。
- 生命周期：30s 定时任务先 `CloseExpiredExams`（无 attempt 的 assigned/waiting → absent；无人作答 → 考试 ended），再 `FinalizeExpiredAttempts` 自动收卷；仍有人在作答时不提前关闭。
- 阅卷：`exams.rules.review_mode`（single/double，默认 single）+ `review_threshold`（未配置按满分 20%）；一评/二评分差 ≤ 阈值取平均，> 阈值生成三评仲裁，仲裁分即为最终分；轮次任务按当前待评任务数最少自动分配，并排除同一题前一轮的评阅人；未配置阅卷教师时留在公共认领池。
- 范围：`exam_proctors` 为空时该考场对所有监考员开放，配置后即收紧；`reviewer` 仅见分配给自己的任务（未分配任务对全部阅卷教师可见），`exam_admin`/`org_admin` 不受限。
- 通知：考试发布通知全部考生、成绩发布通知对应考生，`status='sent'`；`(user_id, source_type, source_id)` 去重，重复发布不重复发送。

## 当前版本：v0.3 后端业务闭环（2026-10-31 完成）

- 目标：把 `/api/v1` 下所有业务骨架接口从「空列表 / 501」变为真实实现，打通「题库 → 组卷 → 发布考试 → 考生作答 → 自动判分 → 人工阅卷 → 成绩发布 → 统计」主链路。
