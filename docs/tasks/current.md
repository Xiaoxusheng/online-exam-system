## v1.0 功能补齐：导入导出、质量分析、成绩更正与申诉（2026-11-01 完成）

- 背景：v0.5/v0.6 把前端接上真实接口并加固了范围与令牌，但需求文档里仍有一批"未实现"功能。本轮把可独立交付的部分全部做完，并部署到腾讯云服务器 80 端口。
- 结果：4 个 Task 全部完成；后端 E2E 从 218 → 331 项、安全回归 60 → 95 项、前端冒烟 33 → 47 项、新增视觉验收 20 项，全部通过，控制台无报错。

### 做什么

1. Excel 通道：`internal/excel`（excelize）+ 模板下载、批量导入（逐行校验、题干重复跳过、自动发布、逐行报告）、题目导出（与模板同构，可回环导入）、成绩导出（成绩 + 汇总双表、逐行水印、审计）。
2. 质量分析：`/analytics/exams/{id}/items` 逐题正确率/得分率/未作答/区分度（前后 27% 分组）/选项分布；`/analytics/knowledge-points` 用 `GROUPING SETS` 一次算出知识点汇总与逐次考试趋势；前端数据分析页拆成三个页签。
3. 成绩更正与申诉：迁移 0006 新增 `score_adjustments` / `score_appeals`；管理端按题更正（保留原记录、状态跟随原记录、通知考生、写审计）+ 更正历史；考生端整卷或单题申诉、重复申诉唯一约束、管理端处理并通知。
4. 连续批阅与通知：`/review-tasks/{id}/neighbors` 给出队列位置与上一份/下一份，阅卷抽屉底部导航 + 提交后"继续批阅下一份"；迁移 0007 预置五个通知模板，`source_type` 即模板编码，`PUT /notification-templates/{id}` 编辑、`GET /notification-logs` 查全机构发送记录。

### 不做什么（v1.0 明确排除）

- 不做编程题沙箱、人脸核验、AI 行为检测、双机位、抓拍存储与对象存储上传。
- 不接短信/邮件服务商：模板与发送记录做完整，通道仍只落站内消息。
- 不做富文本/公式编辑器与题图上传，不改判分内核与快照结构。
- 不引入图表库：分析页继续用 SVG/CSS 自绘，保持包体可控。
- 不做多机构自助注册、CI 与 Docker 化部署。

## v0.6 数据范围、认证加固与安全测试（2026-11-01 完成）

- 背景：v0.5 功能已闭环，但需求 A-02（RBAC + 数据范围）只做到机构级；登录无限流与刷新令牌；前端单包 1.09 MB；缺少系统性的安全与功能回归脚本。
- 目标：把「能演示」推进到「可交付评审」。

### 做什么

1. 请求级身份解析：每次请求按 token 重新加载账号（禁用/改角色立即生效），构造调用者数据范围对象。
2. 数据范围强制：`org / campus / class / self` 四级作用到用户名册与成绩读取；未知范围按拒绝处理；学生读取成绩明细限定本人已发布。
3. 题库可见性：个人题库仅创建者可见（机构/校区范围题库按机构级处理，校区级待题库携带 campus_id 后再收紧）。
4. 登录限流：账号与 IP 双维度失败计数，超限返回 429 + Retry-After，成功登录清零并写审计。
5. 刷新令牌：`refresh_tokens` 表（哈希存储、轮换、吊销、重用检测），登录下发、`/auth/refresh` 轮换、登出吊销；前端 401 自动续期一次后重试。
6. 前端分包：路由级懒加载 + vendor 手动分包，主包体积下降。
7. 测试：新增 `scripts/security_check.mjs`（注入/越权/篡改/限流/令牌轮换/答案泄露）与 `scripts/smoke_ui.mjs`（全路由爬取 + 控制台零报错）。

### 不做什么

- 不做分布式限流（单实例内存计数，多副本需换 Redis，已在文档标注）。
- 不做短信/邮件验证码、MFA、IP 白名单。
- 不做 campus 级题库（缺 bank.campus_id 字段，先记录）。
- 不改业务状态机与既有接口语义（仅新增字段与端点）。

## v0.5 前端接入真实接口（2026-10-31 完成）

- 背景：后端 v0.3/v0.4 已交付完整业务接口与治理能力，`web/` 仍是 UI 骨架（除登录与工作台）。本轮把管理端与考生端全部接到真实 `/api/v1`。
- 目标：跑通「建题 → 组卷 → 审核 → 建考试 → 编排 → 发布 → 考生作答 → 交卷 → 阅卷（双评/仲裁）→ 成绩发布 → 分析」的端到端可用界面，监考中心接 WebSocket 实时流。
- 结果：8 个 Task 全部完成，累计 6 个提交；实机断言 25（角色/通知）+ 17（系统管理）+ 18（题库）+ 20（组卷考试）+ 27（阅卷成绩分析）+ 14（监考实时）+ 19（考生端）= 140 项全部通过，控制台无报错。

### 做什么

1. 数据地基：`apiRequest` 暴露 `pagination`；`queryKeys` 工厂；按模块封装 API 与 TypeScript 类型；路由与侧栏按角色可见（未登录跳转已有）。
2. 系统管理：账号与角色（筛选/新建/编辑/停用/重置密码）、组织架构（校区+班级）、审计日志检索、通知中心与顶栏真实未读。
3. 题库：题库列表/创建、题目多条件筛选与分页、按题型的创建/编辑抽屉（content/answer/score_rule 表单）、发布与版本提示。
4. 试卷与考试：试卷列表、组卷编辑器（固定/AB 选题 + 随机规则）、提交审核与审核通过；考试列表、创建表单（选卷/时间窗/规则/考生与班级编排）、发布、考生名单、监考与阅卷名单配置。
5. 阅卷、成绩与分析：任务池（我的/待认领）、评分抽屉（轮次、双评、仲裁标记、匿名）、成绩列表与逐题明细、按考试发布、成绩分析（统计卡 + 分数段自绘条形）。
6. 监考中心：考试选择、概览卡、事件流与筛选、处置弹窗、WebSocket 实时推送（断线重连 + 轮询兜底）。
7. 考生端：我的考试、作答页（题目导航、答案自动保存与乐观锁冲突处理、倒计时、交卷确认）、我的成绩。

- 目标：完成可运行的前后端工程骨架，登录可用，全模块路由/页面/数据表就位，为 M1 功能填充打底。

### 做什么

1. 单仓工程：`server/`（Go + chi + pgx）、`web/`（React 19 + Vite + antd 5）。
2. PostgreSQL 16 全量 schema（对应需求第 8 节数据模型），可重复执行的迁移器。
3. 登录鉴权闭环：bcrypt 密码、JWT、`/auth/login` `/auth/me` `/auth/logout`、登录审计、种子管理员。
4. 全模块 API 路由骨架（鉴权 + 角色中间件已生效；列表空数据，写操作 501）。
5. 前端：登录页、后台布局、工作台、全部模块路由与占位页（Loading/Empty 状态）。
6. 文档：AGENTS.md、架构、API 契约、本计划；README 快速启动。
7. 验证：Go build/vet/test、前端 typecheck/build、浏览器实机登录截图。

### 不做什么（v0.1 明确排除）

- 不实现题库/组卷/考试/答卷/监考/阅卷/成绩的业务逻辑（仅路由骨架）。
- 不做 WebSocket、判题沙箱、文件上传、短信/邮件、人脸核验、AI 检测。
- 不做多租户、支付、小程序/App、家长端。
- 不做刷新令牌/Token 吊销、Redis 限流（后续安全任务补）。
- 不做生产 Docker 部署与 CI（M1 收尾时补）。
- 不为每个模块新建计划文档（本文档为唯一进度源）。

## 技术决策（已确认 2026-10-31）

- 数据库：PostgreSQL 16（本机复用 StockFlow 的 PG 实例，独立库 `online_exam`）。
- 一期范围：全量骨架 + 登录（用户选择）。
- 仓库：单仓 `server/` + `web/`。
- 端口：API 8081、Web 5174（8080/5173 被 StockFlow 占用）。
- 后端：chi + pgx + 手写 SQL，不引 ORM；JWT HS256；bcrypt cost 12。
- 前端：React 19 + TS + antd 5，主题飞书蓝 #3370FF，TanStack Query + Zustand。

## 已知问题 / 后续改进

- 前端单包 1.08 MB（gzip 343 KB），后续用路由懒加载 + vendor 分包优化。
- 无登录失败限流与刷新令牌；按安全任务在 M1 内补齐。
- 工作台「待审核试卷」当前仅统计试卷，题目审核待题库模块落地后合并。
- 双评分差阈值按绝对分值（`review_threshold` 单位：分）配置，未提供按满分百分比配置（缺省取满分 20%）。
- 监考房间仅有每考试 64 连接上限与慢消费者断开，未做连接级鉴权尝试限速；WS Token 走查询参数（浏览器限制），日志不记录查询串。
- 到期自动结束依赖 30 秒轮询，最大延迟约 30 秒；对实时性要求更高时需改为自适应轮询或 LISTEN/NOTIFY。
- 未实现深色模式（当前产品定位为浅色 SaaS，需求未要求）。
